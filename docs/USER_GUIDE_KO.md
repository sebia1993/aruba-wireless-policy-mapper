# WLC Role ACL Collector 사용자 설명서

## 1. 이 프로그램의 목적

이 프로그램은 Aruba AOS8 무선랜 컨트롤러에 접속해서 다음 정보를 수집하고 HTML/Excel 보고서로 정리합니다.

- 어떤 SSID 사용자가 어떤 Role을 받는지
- Role에 어떤 ACL이 적용되어 있는지
- ACL의 Source, Destination, Service, Action이 무엇인지
- Alias가 있으면 해당 Alias 안에 어떤 host, network, range가 있는지
- 특정 Role에서 출발지 IP와 목적지 IP를 입력했을 때 ACL 기준으로 허용/차단되는지

## 2. 기본 보안 정책

현재 프로그램은 보안모드가 기본값입니다.

- 장비 IP, ID, Password는 프로그램 실행 시 직접 입력합니다.
- GUI에서 사내 Role 대역표를 선택하면 내부용 보고서에 실제 Role 대역과 WLC 비교 상태가 표시됩니다.
- Role 대역표의 전체 파일 경로나 내부 대역 값은 run.log에 남기지 않습니다.
- HTML Access Check 조회 이력은 기본 저장하지 않습니다.
- 생성된 보고서에는 WLC에서 수집한 ACL, Alias, 설정 정보가 포함될 수 있으므로 외부 공유 전 반드시 내용을 확인해야 합니다.

## 3. 실행 전 준비 사항

다음 정보가 필요합니다.

- WLC IP
- Username
- Password
- Enable password가 필요한 환경이면 Enable password
- 접속 방식: 기본 SSH, 필요 시 Telnet
- 결과 저장 폴더
- 선택 사항: 사내에서만 사용하는 Role 대역표 Excel

장비 접속 대상 주의:

- 이 프로그램은 Mobility Master(MM)가 아니라 실제 WLC 컨트롤러에 접속해야 합니다.
- MM IP를 입력하면 Role/ACL 수집 결과가 누락되거나 장비 명령 결과가 예상과 다를 수 있습니다.

사내 Role 대역표를 사용할 경우 `Role_Networks` Sheet에 아래 컬럼이 있어야 합니다. 프로그램은 `Role_Networks` Sheet가 있으면 Sheet 순서와 관계없이 그 Sheet를 우선 읽습니다. `Role_Networks` Sheet가 없을 때만 기존 호환성을 위해 첫 번째 Sheet를 읽고 화면에 fallback 안내를 표시합니다. `네트워크 대역`은 CIDR 형식(`10.40.1.0/24`)을 권장합니다.

| 컬럼 | 예시 |
| --- | --- |
| Role 이름 | corp-employee |
| 네트워크 대역 | 10.40.1.0/24 |
| 서브넷마스크 | 255.255.255.0 |
| 설명 | 본사 임직원 무선 |
| 소유부서 | 네트워크팀 |
| 비고 | 내부용 |
| 마지막 확인일 | 2026-06-29 |

`서브넷마스크`는 CIDR을 쓰지 않고 `10.40.1.0`처럼 네트워크 주소만 입력할 때 필요합니다. `설명`, `소유부서`, `비고`, `마지막 확인일`은 관리용 선택 컬럼이며 보고서 매칭에는 사용하지 않습니다.

Excel 파일은 실제 `.xlsx` 또는 `.xlsm` 형식이어야 합니다. CSV나 구형 `.xls` 파일의 확장자만 `.xlsx`로 바꾸면 열 수 없습니다.

GUI의 `작성법` 버튼을 누르면 앱 내부 팝업으로 작성 규칙과 예시를 확인할 수 있습니다. `샘플 열기` 버튼을 누르면 제공된 `config\role_networks.example.xlsx`가 열립니다. 샘플 파일에는 실제 입력용 `Role_Networks` 시트와 설명용 `작성가이드` 시트가 있습니다. `작성가이드` 같은 안내 Sheet가 첫 번째에 있어도 `Role_Networks` Sheet가 있으면 안내 Sheet는 읽지 않습니다.

## 4. Windows GUI 실행 방법

배포 ZIP을 받은 경우:

1. ZIP 파일을 사내 PC에 압축 해제합니다.
2. `WlcRoleAclCollectorGUI.exe`를 실행합니다.
3. Windows SmartScreen 경고가 나오면 회사 보안 정책에 따라 실행 여부를 확인합니다.

ZIP에는 GUI 실행 파일과 로컬 Web 실행 파일이 포함됩니다.

- `WlcRoleAclCollectorGUI.exe`: 일반 수집과 안전 진단을 실행하는 Windows 화면

ZIP 안에는 설명서가 두 가지 형식으로 포함됩니다.

- `USER_GUIDE_KO.html`: 브라우저로 바로 열어 보기 좋은 사용자 설명서
- `USER_GUIDE_KO.md`: Markdown 원본 설명서
- `DEVELOPER_GUIDE_KO.html`: 브라우저로 바로 열어 보기 좋은 개발자 설명서
- `DEVELOPER_GUIDE_KO.md`: Markdown 원본 개발자 설명서
- `ERROR_CODES_KO.html` / `ERROR_CODES_KO.md`: 외부 공유 가능한 오류 코드 설명
- `DIAGNOSTIC_MODE_KO.html` / `DIAGNOSTIC_MODE_KO.md`: 원본 로그 없는 현장 진단 모드 설명
- `SECURITY_MODEL_KO.html` / `SECURITY_MODEL_KO.md`: 민감정보 저장/마스킹 기준

소스 코드 상태에서 실행하는 경우:

```powershell
python -m pip install --require-hashes -r requirements-lock.txt

python -m wlc_role_acl_collector.gui_app
```

### SSH 서버 키 최초 승인

SSH는 승인된 서버 키와 일치할 때만 연결합니다. **Windows GUI와 로컬 Web에서는 별도 CLI 없이 최초 접속 시 화면에서 SSH 지문을 확인합니다.**

1. WLC 관리 화면, 자산대장 또는 네트워크 담당자에게서 SSH 서버 키의 SHA-256 지문을 별도 경로로 확인합니다.
2. GUI에서 `분석 시작` 또는 `안전 진단`을 누르면 로그인 정보를 보내기 전에 서버 키를 자동으로 조회합니다.
3. 처음 보는 키라면 지문 확인창을 표시합니다. 별도 경로에서 확인한 지문과 완전히 일치하는 경우에만 승인하세요. 거절하면 로그인 정보는 전송하지 않습니다.
4. 이미 승인된 키는 별도 창 없이 진행하고, 승인된 키와 달라졌다면 자동 변경 없이 차단합니다. 장비 교체 등 정당한 변경인지 확인하기 전에는 `known_hosts`를 삭제하거나 바꾸지 마십시오.

Web에서는 WLC 정보 입력 후 `수집 실행`을 누르면 신규 SSH 서버의 SHA-256 지문 승인창이 열립니다. 별도 관리 경로에서 확인한 지문과 일치할 때만 승인 후 수집을 진행합니다. 이미 승인된 지문은 자동 확인하고 변경된 지문은 연결을 차단합니다.

Telnet은 서버 키 검증과 암호화를 제공하지 않습니다. 계정과 장비 출력이 평문으로 전송되므로 격리된 관리망에서 위험을 승인한 경우에만 사용하고, SSH 실패 시 대체 수단으로 자동 선택되지 않습니다.

### Streamlit 웹앱을 사용하는 경우

통합 ZIP의 `web\start_webapp.cmd`를 실행한 뒤 같은 PC에서 `http://127.0.0.1:8763`을 엽니다. 기본 설정에서는 다른 PC가 접속할 수 없습니다.

접속 주소는 `127.0.0.1`로 고정됩니다. `webapp_settings.cmd`에서는 포트만 바꿀 수 있으며, 인증·TLS가 없는 원격 노출을 막기 위해 외부 인터페이스 바인딩은 지원하지 않습니다.

같은 WLC에서 다른 웹 수집이 진행 중이면 새 작업은 시작되지 않습니다. 기존 작업이 끝난 뒤 다시 실행합니다.

웹 화면에서는 `접속 방식`을 먼저 선택합니다. SSH는 접속 포트 22, Telnet은 23이 자동 기본값으로 표시됩니다. 그 다음 `WLC IP`, 선택 항목인 `보고서 표시 이름`, `장비 ID`, `장비 PW`, 필요 시 Enable password를 입력합니다.

입력 오류는 `입력값을 확인하세요`와 함께 잘못된 항목을 표시합니다. 수집·파싱·보고서 생성 중 실패하면 결과 영역에 `오류 코드`, `실패 단계`, `권장 조치`가 먼저 표시되고, 내부 상태값은 `기술 세부 정보`를 펼쳤을 때만 보입니다. Python traceback이나 내부 파일 경로는 일반 결과 화면에 표시하지 않습니다.

## 5. GUI 입력 항목 설명

GUI의 기본 흐름은 `접속 정보 입력 → 분석 시작 → 결과 상태 확인 → HTML 보고서 확인`입니다.

- 왼쪽: WLC 접속 정보, 인증 정보, 결과 저장 위치 입력
- 결과 영역: SSID/Role 수치, `정상 완료·부분 완료·수집 실패`, 실패 명령 수, 영향 안내 표시
- `분석 시작` 옆 `실행 취소`: 현재 명령이 끝난 뒤 장비 세션을 닫고 안전하게 중단
- 고급 옵션: 사내 Role 대역표, Timeout seconds, 안전 진단
- 수집 로그: 기본 숨김이며 필요할 때 `수집 로그 표시`로 확인
- 상단 배지: 보안모드, 읽기 전용 수집, AOS8 WLC 대상 표시

| 항목 | 설명 |
| --- | --- |
| WLC IP | 접속할 실제 WLC 컨트롤러 IP. MM이 아님 |
| 보고서 이름(선택) | 보고서에 표시할 이름. 비워두면 `wlc-장비IP` 형태로 자동 지정 |
| Protocol | 기본 `ssh`, 필요 시 `telnet` 선택 |
| Port | SSH는 기본 22, Telnet은 기본 23 |
| Username | WLC 로그인 계정 |
| Password | WLC 로그인 비밀번호 |
| Enable password | enable 권한 진입이 필요한 경우 입력 |
| Output | 결과 파일을 저장할 폴더 |

아래 항목은 `고급 옵션 표시`를 눌렀을 때 나타납니다.

| 항목 | 설명 |
| --- | --- |
| 사내 Role 대역표 | 선택 사항. 선택하면 내부용 HTML/Excel 보고서에 실제 Role 대역과 WLC 비교 상태 표시 |
| Timeout seconds | 명령 하나의 응답 대기 시간. 5~600초만 허용하며 기본값은 60초 |
| 안전 진단 | 원본 장비 출력 없이 접속/명령 단계와 오류 코드만 확인 |

`사내 Role 대역표` 영역에는 세 가지 버튼이 있습니다.

| 버튼 | 설명 |
| --- | --- |
| 파일 선택 | 실제 사내 Role 대역표 Excel을 선택하고 즉시 검증 |
| 작성법 | 앱 내부 팝업으로 필수 컬럼, CIDR 예시, 오류 방지법 확인 |
| 샘플 열기 | 제공된 `role_networks.example.xlsx` 템플릿 열기 |

입력이 끝나면 `분석 시작` 버튼을 누릅니다.

수집이 완료되면 `HTML 보고서 열기` 버튼을 먼저 눌러 결과를 확인합니다. Excel 원본 표가 필요하면 `Excel 열기`, 실행 폴더나 run.log가 필요하면 `결과 폴더 열기`를 사용합니다.

수집 상태 의미:

| 상태 | 의미 | 사용자 조치 |
| --- | --- | --- |
| 정상 완료 | 필수/선택 수집 명령이 모두 성공 | HTML의 Unresolved와 세부 ACL 확인 |
| 부분 완료 | 보고서는 생성됐지만 선택 명령 하나 이상 실패 | 실패 명령, 영향 영역, 영향 Role/SSID 확인 후 해당 정보는 재수집 전 확정 판단 금지 |
| 수집 실패 | `show configuration effective` 같은 필수 데이터 없음 | 생성 결과를 정책 판단에 사용하지 말고 접속·권한·명령 문제 해결 후 재실행 |
| 사용자 취소 | 사용자가 실행 취소를 요청함 | 부분 raw/run.log는 참고만 하고 필요하면 처음부터 재실행 |

`실행 취소`는 실행 중인 스레드나 접속을 강제로 끊지 않습니다. 현재 장비 명령이 응답하거나 해당 명령의 Timeout에 도달하면 다음 명령을 실행하지 않고 세션을 종료합니다. 프로그램 창을 닫을 때도 실행 중 작업의 취소 여부를 묻고, 세션과 파일 정리가 끝날 때까지 창을 유지합니다.

명령별 Timeout과 별개로 전체 수집은 최대 60분입니다. 많은 Role/Alias에서 반복 Timeout이 발생해 60분 상한에 도달하면 가능한 결과까지만 부분 완료로 만들고 `duration_limit` 실패를 표시합니다.

다중 모니터 사용 시 참고:

- 프로그램 창은 현재 모니터의 작업영역 안에 들어오도록 자동 보정됩니다.
- 모니터마다 배율이나 해상도가 달라도 창이 너무 크게 남아 하단 버튼이 잘리는 일을 줄이도록 설계되어 있습니다.
- 작은 모니터에서는 좌측 입력 영역을 스크롤해서 볼 수 있습니다.

## 6. 수집 후 생성되는 파일

결과는 기본적으로 아래 위치에 생성됩니다.

```text
%USERPROFILE%\Documents\WlcRoleAclCollector\outputs\<실행시각>\
```

주요 파일:

| 파일 | 설명 |
| --- | --- |
| `ssid_role_acl_report.html` | 운영자가 보기 쉬운 HTML 보고서 |
| `ssid_role_acl_report.xlsx` | Excel 보고서 |
| `run.log` | 실행 과정과 오류 원인 로그 |
| `raw\<controller>.txt` | 수집한 원본 명령 결과 일부 |
| `report_status.json` | 보고서 저장 상태와 수집 완전성. 파일 `status`가 `completed`가 아니면 HTML/Excel을 완료본으로 사용하지 않음 |

주의: `show user-table` 원문은 개인정보 노출을 줄이기 위해 raw 파일에 그대로 저장하지 않습니다. 다만 ACL, Alias, WLC 설정에는 내부 IP나 정책명이 포함될 수 있습니다.

`report_status.json`에는 서로 다른 두 상태가 기록됩니다.

- `status`: HTML/Excel 파일 저장 상태인 `writing`, `completed`, `failed`
- `collection_status`: 장비 명령 수집 상태인 `completed`, `partial`, `failed`

파일 `status=completed`라도 `collection_status=partial`이면 일부 장비 명령이 실패한 보고서입니다. HTML 첫 화면의 영향 범위와 권장 조치를 확인해야 합니다.

## 7. HTML에서 정책 설명 작성하기

생성된 `ssid_role_acl_report.html`을 브라우저로 열면 **Role 내부 탭형 통합 화면(C안)**이 나타납니다. 왼쪽에서 Role을 선택한 뒤 `정책·주석`, `ACL 접근 판정`, `수집 상세` 탭을 이용합니다. 수집 후에는 장비에 다시 접속하지 않고 정책을 확인하거나 주석을 작성할 수 있습니다.

**Role 옆 편집:** 제목 옆의 `SSID 명`은 사용자가 직접 입력하는 보고용 값이며, `단말 구분`은 `윈도우 PC`, `맥북`, `mobile`, `ETC` 또는 `미지정`을 선택합니다. 예전에 저장한 `PC`는 `PC (기존 분류)`로 표시해 보존하며, 운영체제를 확인하지 않은 기존 데이터를 임의로 윈도우 PC로 변경하지 않습니다. 확인 후 사용자가 직접 구분을 바꿀 수 있습니다. 두 필드는 기존에 수집된 SSID 연결 정보와 별도로 저장되며, 값을 바꾸면 해당 Role의 확인 상태가 다시 `미확인`이 됩니다. 기존 주석을 지우지 않고 관리할 수 있습니다.

1. 왼쪽 `Role / 장비 / SSID 검색`으로 대상을 찾고 Role 이름을 누릅니다. 같은 이름의 Role도 컨트롤러별로 구분합니다.
2. `보고용 Role 설명`에 업무 목적, 대상 사용자, 주요 접근 범위와 예외를 적습니다. `설명 틀 넣기`는 빈 메모에만 틀을 넣습니다.
3. `정책·주석` 탭의 `ACL 행별 주석`에서 정책 목적과 허용·차단 근거를 적습니다. `global-sacl`, `re-guard`, `logon-control`은 기본 숨김이며 `공통 ACL 함께 보기`로 표시할 수 있습니다. 숨겨진 규칙도 작업 파일과 내보내기 원본에 보존됩니다. 관측 사용자 0명인 Role 역시 삭제하지 않습니다.
4. 확인 상태를 `미확인`, `확인 완료`, `이전 설명 재사용`, `재확인 필요` 중에서 정합니다. 설명을 수정하면 다시 `미확인`이 됩니다. 빈 설명도 유효한 작업 상태입니다.
5. `Alias · ACL 연결 순서 · 수집 확인 사항`을 펼쳐 해석에 필요한 정보를 확인합니다. `변경·확인 필요 항목 보기`는 재사용 메모, 변경 사항, 불완전한 수집과 확인 사항이 있는 Role을 추려 줍니다.
6. **작업 저장**을 눌러 최신 작업 파일을 내려받습니다.

수집 상태가 `일부 수집`, `수집 실패`, `수집 범위 미확인`이면 누락된 규칙을 삭제된 정책으로 단정하지 마십시오. 서비스 정의나 Alias 정보가 불완전한 경우에도 현재 설명을 확정하기 전에 확인해야 합니다.

### Role 내부 탭 이용 방법

- `정책·주석`: Role 설명, 수기 SSID·단말 구분, ACL 규칙별 주석과 확인 상태를 편집합니다. `global-sacl` / `re-guard` / `logon-control` 표시 여부는 화면 표시만 바꾸고 수집 데이터는 변경하지 않습니다. 해당 Role에 이 세 공통 ACL만 있더라도 수집 실패가 아닌 기본 숨김으로 안내하며, 필요하면 전체 내용을 다시 확인할 수 있습니다.
- `ACL 접근 판정`: 기존 Access Check를 재사용하여 입력한 출발지·목적지·서비스를 수집된 ACL/Alias 범위에서 보조 판정합니다. 이는 실제 네트워크 패킷 송수신 테스트가 아닙니다.
- `수집 상세`: 결론 요약, SSID/Role 관계, 원본 Role ACL Detail, Alias 상세와 수집 신뢰도 정보를 확인합니다. 이 화면의 설명은 읽기 전용이며 주석 편집 결과가 반영됩니다.

`ACL 접근 판정`과 `수집 상세`는 **현재 작업과 원본 보고서의 수집본이 일치할 때만** 활성 데이터를 표시합니다. 다른 작업을 열거나 독립 HTML로 내보내어 원본이 없는 경우 오래된 Access Check 데이터를 연결하지 않고 안내를 표시합니다. 원본 화면의 `Show zero-user roles`, `Show other ACLs`, `Raw 보기`는 화면 표시만 바꿉니다. PDF/Excel 보고 범위는 별도로 선택합니다.

`수집 신뢰도`는 수집의 완전성을 뜻하며 정책 적절성의 보증이 아닙니다. ClearPass/RADIUS `동적 Role 참고`는 실제 사용자 할당 Role을 직접 관측한 결과와 구분합니다.

## 8. 작업 저장·재사용·보고서 내보내기

### 작업 파일을 기준으로 이어서 작성

| 기능 | 저장하거나 적용하는 내용 |
| --- | --- |
| `작업 저장` | 수집본, Role/ACL 설명, Role별 수기 SSID·단말 구분, 확인 상태, 출처, 변경·미연결 항목을 `.aruba-project.json`으로 다운로드 |
| `작업 열기` | 선택한 JSON 또는 지원되는 주석 HTML의 수집본과 주석 전체를 현재 작업으로 복원 |
| `이전 주석 가져오기` | 현재 수집본을 유지하면서 이전 작업의 설명을 대조하고 재사용 |
| `주석 포함 HTML 저장` | 현재 수집본과 주석, 편집 기능과 출력 모듈을 포함한 독립 HTML 편집기 다운로드 |

**JSON 작업 파일이 다음 작업을 이어 갈 기준 파일입니다.** 저장 버튼은 새 파일 다운로드를 요청하며, 이미 디스크에 있는 원본 파일을 자동으로 덮어쓰지 않습니다. 브라우저의 다운로드 완료와 저장 위치를 확인하고 가장 최근 파일을 보관하십시오. Excel과 PDF는 보고용 산출물이며, 편집 내용을 다시 가져오는 작업 원본으로 사용하지 않습니다.

브라우저 임시저장은 복구를 돕는 보조 수단입니다. 같은 작업·수집본·기준 버전에서 남은 내용이 있으면 파일 내용부터 표시하고 `임시작업 복구` 또는 `임시작업 버리기`를 선택하게 합니다. 복구는 빈 설명과 확인 상태까지 적용하므로 복구 후에도 작업 파일을 저장하십시오. 개인정보 보호 설정이나 저장 용량 제한으로 임시저장이 불가능해도 화면의 작업과 파일 다운로드는 사용할 수 있습니다. 다른 PC로 이동할 때는 다운로드한 작업 파일을 사용합니다.

### 새 수집본에 이전 설명 가져오기

1. 새로 수집한 HTML을 열거나 `작업 열기`로 새 수집본의 작업 파일을 엽니다.
2. `이전 주석 가져오기`에서 이전 JSON 또는 지원되는 주석 HTML을 선택합니다.
3. 컨트롤러 주소가 없는 이전 HTML이면 장비 연결 화면에서 이전 장비와 현재 장비의 대응을 직접 선택합니다. 이름만 같은 장비는 자동 연결하지 않습니다. 연결하지 않으면 해당 설명은 미연결 주석으로 보관됩니다.
4. `변경·확인 사항`과 `미연결 주석`을 검토합니다. 원문 전체가 일치하는 단일 규칙을 기준으로 재사용하며, 순번만 같다는 이유로 설명을 옮기지 않습니다. 중복 규칙, 변경된 원문, Alias 구성원·ACL 연결·선행 규칙 변경, 불완전한 수집이나 확인되지 않은 서비스 정의는 추가 확인이 필요합니다.
5. 재사용한 메모는 자동으로 `확인 완료`가 되지 않습니다. 현재 정책과 비교한 뒤 상태를 정하고 `작업 저장`으로 새 파일을 보관합니다.

자동 가져오기는 현재 주석을 유지하고 충돌한 이전 설명을 미연결 항목으로 보존합니다. 미연결 항목의 `연결할 Role/규칙`을 골라 `선택한 행에 주석 연결`을 누르면 `재확인 필요` 상태로 옮깁니다. 선택한 행에 이미 메모가 있으면 기존 메모는 미연결 목록에 따로 보관됩니다. 원문, 컨트롤러, Role과 출처를 비교한 뒤 연결하십시오. 지원하지 않는 버전이나 손상된 파일은 현재 작업을 교체하지 않고 오류를 표시합니다. 가져올 파일은 최대 50 MiB이며, 개별 메모와 전체 작업 내용에도 별도 크기 한도가 있습니다.

### 보고 범위와 Excel/PDF

`보고 범위`에서 다음 중 하나를 정한 뒤 `Excel 저장` 또는 `PDF 저장`을 누릅니다.

| 보고 범위 | 포함 항목 |
| --- | --- |
| `전체 정책` | 현재 수집본의 전체 정책과 주석, 변경·미연결 항목 |
| `선택한 Role` | 왼쪽 체크박스로 고른 Role과 해당 규칙·관련 정보. Role 이름을 눌러 여는 동작과 체크박스 선택은 별개 |
| `변경·확인 필요 항목` | 변경·재사용·미연결 메모와 불완전한 수집, 서비스 정의 등 확인할 문맥이 있는 항목 |

검색이나 원본 화면에서 행을 숨겨도 보고 범위가 자동으로 바뀌지 않습니다. `목록 전체 선택`은 현재 검색·필터 목록의 Role을 체크하며 `선택 해제`로 비울 수 있습니다. 출력에는 최신 설명과 프로젝트/수집본 ID, 버전, 수집·수정·내보내기 시각이 들어갑니다.

Alias 상세에는 대상 Role이 속한 장비의 Alias 전체가 수집 문맥 확인용으로 포함됩니다. 수집본 생성 시각은 이 도구에서 작업 데이터를 만든 시각입니다.

`Excel 저장`은 실제 `.xlsx` 파일을 생성하며 **보고 요약 / Role 설명 / ACL 상세 / 변경·확인 사항 / Alias 상세** 다섯 시트를 포함합니다. `Role 설명` 시트에는 수집 SSID와 별도로 직접 입력한 `SSID 명`, `단말 구분` 열이 포함됩니다. PDF의 Role 설명에도 이 두 값이 표시됩니다. 메모와 원문은 문자열로 저장합니다. 셀 한도 32,767자를 넘는 내용은 같은 `레코드 번호`의 `조각 / 전체` 순서대로 연속 행에 나누어 보관하므로, 긴 주석은 해당 열의 조각을 순서대로 이어 읽습니다.

`PDF 저장`은 선택한 보고 범위로 별도 인쇄 창을 열고 브라우저의 인쇄 기능을 호출합니다. 대상을 `PDF로 저장`으로 정하고 저장 위치를 확인하십시오. 팝업이 차단되면 이 파일의 팝업을 허용한 뒤 다시 시도합니다. 인쇄 취소와 실제 파일 저장은 브라우저에서 결정하며 편집 화면의 내용은 유지됩니다.

PDF의 각 상세 행에는 컨트롤러 이름과 함께 장비 주소·접속 포트·설정 범위 및 컨트롤러 식별자가 표시됩니다. Role·규칙·Alias 식별자도 함께 표시하므로, 여러 장비의 이름과 정책 이름이 같아도 주석의 대상을 구분할 수 있습니다. 이전 자료에 주소 정보가 없으면 주소를 추측해서 채우지 않습니다.

`수집 상세` 탭에 있는 `선택 Role PNG 저장`은 원본 화면의 현재 Role과 표시 상태를 이미지로 보관하는 기존 기능입니다. PDF/Excel의 보고 범위와 별개이며, 내용이 길면 여러 PNG로 나뉠 수 있습니다.

작업 파일과 주석 HTML에도 허용된 정책 원문이 들어갑니다. 사내 Role 대역을 포함하도록 수집한 작업이면 해당 대역이 작업과 보고서에 유지됩니다. GUI의 사내 Role 대역표 선택과 Web의 보고서 포함 옵션에 따른 기존 포함 기준은 그대로 적용됩니다. 계정·비밀번호와 `show user-table` 원문은 작업에 넣지 않지만, 직접 적은 설명이나 정책명에도 민감정보가 있을 수 있으므로 공유 전에 확인하십시오.

이번 기능의 자동·합성 검증은 실제 회사 장비, 사내 파일, Windows 브라우저 및 회사 인쇄 환경에서의 사용자 수동 검증을 대신하지 않습니다. 해당 현장 검증은 사용자가 별도로 수행할 범위입니다.

## 9. Access Check 사용 방법

Role을 선택하고 `ACL 접근 판정` 탭을 누르면 해당 Role의 수집본 기준 Access Check를 사용할 수 있습니다. 선택한 Role의 원본이 없는 경우에는 판정이 제공되지 않습니다. 독립 주석 HTML에는 원본 Access Check가 포함되지 않습니다.

Access Check는 선택한 Role 안에서 ACL 이름이 Role 이름과 정확히 같은 ACL만 검사합니다. 예를 들어 Role이 `guest-logon`이면 ACL 이름도 정확히 `guest-logon`인 항목만 판정 대상입니다. `guest-logon-acl`처럼 비슷하지만 이름이 다른 ACL은 Role ACL Detail에는 보일 수 있지만 Access Check 판정에는 사용하지 않습니다.

Role ACL Detail에서 Role 버튼을 클릭하면 Access Check의 Role 선택값도 같은 Role로 자동 변경됩니다. Role별 ACL을 보면서 바로 출발지/목적지 IP 검사를 이어갈 때 사용합니다.

입력 항목:

| 항목 | 설명 |
| --- | --- |
| Role | 확인할 사용자 Role |
| Source IP | 사용자 또는 단말의 출발지 IP |
| Destination IP | 접근하려는 목적지 IP |
| Service | 선택 사항. 기본값은 `자동 - Source/Destination 기준`이며, Source/Destination이 맞는 ACL을 위에서 아래 순서로 찾습니다. 특정 service ACL에 매칭되면 조건부로 표시됩니다. |

결과 의미:

| 결과 | 의미 |
| --- | --- |
| 허용(Allowed) | permit ACL에 매칭됨 |
| 차단(Blocked) | deny ACL에 매칭됨 |
| NAT/특수 Action 허용 | src-nat, dst-nat, redirect, route, tunnel, forward 같은 특수 action에 매칭됨 |
| 기본 차단(Implicit deny) | 매칭되는 ACL이 없어 기본 차단으로 판단 |
| 판정 불가(ACL/Alias 정보 불완전) | 앞선 ACL이 매칭될 가능성이 있지만 Alias/name 상세가 없어 허용·차단을 확정할 수 없음 |
| 조건부 | Service 자동 매칭 상태에서 특정 service ACL에 매칭되어 추가 확인이 필요 |
| 일치하는 Role ACL 없음 | Role 이름과 정확히 같은 ACL이 없어 Access Check로 판정할 수 없음 |

중요한 제한:

- Access Check는 보고서 안에 포함된 ACL/Alias 데이터를 기준으로 판단합니다.
- 앞선 규칙의 Alias/name 정보가 불완전하면 뒤 규칙으로 넘어가 허용·차단을 확정하지 않고 `판정 불가`를 표시합니다.
- Access Check는 ACL 이름이 Role 이름과 정확히 같은 ACL만 검사합니다.
- Service를 선택하지 않으면 `자동 - Source/Destination 기준` 모드로 동작하며, ACL 표시 순서대로 첫 번째 Source/Destination 매칭 규칙을 찾습니다.
- Service 자동 매칭 결과가 `any`가 아닌 특정 service ACL이면 조건부 판정으로 표시합니다.
- Service object의 실제 TCP/UDP 포트까지 세부 해석하는 기능은 아직 포함되어 있지 않습니다.
- 보안모드에서는 Access Check 이력이 HTML이나 브라우저 저장소에 기본 저장되지 않습니다.
- 사내 Role 대역표를 선택한 내부용 보고서에서는 Source IP가 해당 Role 대역 밖인지 경고합니다. 대역표를 선택하지 않은 보고서에서는 HTML 단독으로 “Source IP가 해당 Role 대역에 속하는지”까지 검증하지 않습니다.

## 10. 사내 Role 대역표 사용 방식

사내 Role 대역표는 사내망에서만 선택하는 내부 기준 파일입니다. 프로그램 안에 저장하지 말고, 사내에서 관리하는 표준 Excel 원본을 실행할 때 선택하는 방식을 권장합니다.

GUI 기본 동작:

- 선택 즉시 Excel 형식과 대역 값을 검증합니다.
- 로드된 Role 수, 대역 수, 중복 제외 건수를 화면에 표시합니다.
- 수집 후 내부용 HTML/Excel 보고서에 실제 Role 대역과 WLC 비교 상태를 표시합니다.
- HTML 상단에 `내부망 전용 보고서` 안내가 표시됩니다.
- run.log에는 파일 경로나 대역 값을 남기지 않고 로드 행 수만 기록합니다.

샘플 Excel 구성:

| 시트 | 용도 |
| --- | --- |
| Role_Networks | 실제 프로그램이 우선 읽는 입력 시트. Sheet 순서와 관계없이 이 이름을 먼저 찾음 |
| 작성가이드 | 작성 규칙, 예시, 주의사항 안내 시트. Role_Networks Sheet가 있으면 읽지 않음 |

Sheet 선택 기준:

- `Role_Networks` Sheet가 있으면 Sheet 순서와 관계없이 그 Sheet를 우선 읽습니다.
- `Role_Networks` Sheet가 없으면 기존 호환성을 위해 첫 번째 Sheet를 읽습니다.
- fallback이 발생하면 화면 상태 메시지에 `Role_Networks Sheet가 없어 첫 번째 Sheet를 읽었다.`가 표시됩니다.

GUI는 사내 Role 대역표를 선택한 경우 내부용 보고서에 실제 대역 정보를 표시합니다. Web에서는 Excel 대역표 업로드 후 보고서 포함 여부를 설정할 수 있습니다.

내부 대역을 포함한 보고서는 외부 반출 금지 대상으로 취급합니다. 장비 수집 실패 및 저장 실패는 화면에서 오류 코드와 권장 조치를 확인하세요.

## 11. 자주 발생하는 오류

| 오류 | 확인할 내용 |
| --- | --- |
| WLC 로그인 인증에 실패했습니다 | ID/PW, 계정 잠금, WLC 로그인 권한 확인 |
| Enable 권한 전환에 실패했습니다 | enable password 필요 여부, 입력값, 계정 권한 확인 |
| WLC에 연결하지 못했습니다 | IP, 방화벽, SSH/Telnet 활성화, 포트 확인 |
| 로그인 후 필수 조회 명령에 실패했습니다 | 로그인은 됐지만 `show configuration effective` 또는 `show rights` 권한/응답 문제 확인 |
| Unable to open Role network Excel file: File is not a zip file | 실제 Excel `.xlsx`가 아니라 CSV/HTML/구형 XLS를 확장자만 바꾼 파일인지 확인 |
| 보고서에 Role이 부족함 | 해당 Role의 `show rights <role>` 명령 권한 또는 수집 로그 확인 |
| Access Check 결과가 예상과 다름 | Service 선택 여부, Alias 상세 수집 여부, 숨겨진 other ACL 표시 여부 확인 |
| 같은 WLC에서 이미 수집 중 | 웹앱의 기존 수집이 끝난 뒤 다시 실행 |
| 부분 완료 | HTML 첫 화면의 실패 명령, 영향 영역, 영향 Role/SSID를 확인하고 해당 영역은 재수집 전 확정 판단하지 않음 |
| Timeout seconds 입력 오류 | 5~600 사이 숫자로 입력 |
| `duration_limit` | 전체 60분 상한에 도달함. 느린 명령과 실패 대상을 확인한 뒤 대상 부하를 고려해 재수집 |
| 장비 세션 정리 경고 | 보고서 데이터는 생성됐지만 `disconnect()` 성공을 확인하지 못함. 프로그램을 종료하고 WLC 관리 세션 상태 확인 |
| 사용자 취소 후 보고서가 없음 | 정상 동작. 취소 실행은 완료 보고서를 만들지 않으며 결과 폴더의 run.log만 참고 |
| `report_status.json`이 `writing` 또는 `failed` | HTML/Excel을 완료본으로 사용하지 말고 수집 로그와 저장 권한 확인 |

## 12. 진단 모드와 오류 코드

현장에서 문제가 발생했지만 원본 로그를 외부로 가져올 수 없는 경우 진단 모드를 사용합니다.

GUI에서 실행하는 경우:

1. `WlcRoleAclCollectorGUI.exe`를 실행합니다.
2. 평소 수집과 동일하게 `WLC IP`, `Protocol`, `Port`, `Username`, `Password`를 입력합니다.
3. `고급 옵션 표시`를 누릅니다.
4. `안전 진단` 버튼을 누릅니다.
5. 완료 후 `HTML 보고서 열기` 또는 `결과 폴더 열기`로 진단 결과를 확인합니다.

GUI 진단 모드는 수집 보고서용 raw 폴더를 만들지 않습니다. 결과 파일에는 단계, 오류 코드, command_id, 안전한 조치 안내만 포함됩니다.

진단 모드는 아래 파일을 생성합니다.

- `diagnostic_summary.json`
- `diagnostic_summary.html`
- `diagnostic_run.log`
- `diagnostic_status.json`

진단 파일에는 원본 장비 출력 대신 단계, 오류 코드, command_id, 안전 메시지만 저장합니다.
`diagnostic_status.json`의 `status`가 `completed`일 때만 JSON, HTML, log 세 파일을 같은 실행의 완료본으로 사용합니다. `writing` 또는 `failed`이면 저장이 끝나지 않았거나 일부 파일 생성에 실패한 상태입니다.

외부 분석 요청 시에는 먼저 아래 값만 전달합니다.

- `primary_code`
- `stage`
- `command_id`
- `raw_output_saved`

오류 코드별 의미는 `ERROR_CODES_KO.html`에서 확인합니다.

개발 중 실제 장비 없이 동작 확인이 필요하면 비식별 Mock 시나리오와 자동 테스트를 사용합니다. 별도 콘솔 실행 모드는 제공하지 않습니다.

## 14. 문제가 생겼을 때 전달하면 좋은 정보

개발자나 담당자에게 문의할 때는 아래 정보를 전달하면 원인 확인이 빠릅니다.

- 프로그램 실행 시각
- WLC IP 또는 Report name
- 오류 메시지 전체
- `run.log`
- 어느 단계에서 멈췄는지: 접속, 명령 수집, 보고서 생성, HTML 확인
- 수집 상태: 정상 완료, 부분 완료, 수집 실패, 사용자 취소
- 부분 완료인 경우 실패 명령 수와 화면에 표시된 영향 영역
- 진단 모드를 실행한 경우 `primary_code`, `stage`, `command_id`

비밀번호와 Role network Excel 원본은 전달하지 마십시오.
